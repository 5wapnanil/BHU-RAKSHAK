PahaarPulse — Gemma Local Vision Inference

Technical Architecture, Open-Weight Model Selection, Implementation Record, and Verification Report • October 2026
Executive Summary: Extends the PahaarPulse Landslide Risk Management system with an on-premises open-weight Vision-Language Model (VLM) provider using Google Gemma 3 4B (gemma3:4b) via the Ollama runtime. The solution guarantees complete offline operational capability during disasters while preserving the existing hosted provider (gemini-3.5-flash), Pydantic schemas, database records, and safety guardrails.

1. System Architecture & Component Interaction

The AI hazard screening subsystem functions as an observational triage assistant. It ingests ground field report photographs and notes from web and mobile applications, evaluates visible geotechnical features, and records structured indicators atomically in PostgreSQL.

3. Evidence-Grounded Geotechnical Screening Rules

The system prompt enforces strict geotechnical screening boundaries:

  • Separation of Evidence: Features in detected_hazards must be directly visible in the attached photograph. Written observer notes are treated as unverified claims and must not be reported as physical visual confirmation.
  • Indeterminate State: If image quality, lighting, perspective, distance, or vegetation obscures the slope, the model defaults to indeterminate. Uncertain reports are never defaulted to low.
  • No Safety Clearances: The model is strictly prohibited from declaring an area "safe" or "cleared" for human occupancy. Output is observational triage only.
  • Uncalibrated Confidence: Confidence scores are explicitly labeled as model self-assessment, not empirical statistical probabilities.

4. Implementation and Resilience Engineering

  • Unified JSON Extraction: parse_gemma_json reliably handles empty responses, whitespace, and markdown code fences (```json ... ```).
  • Ollama Runtime Error Differentiation: Missing models (HTTP 404) generate clear ollama pull gemma3:4b guidance; concurrency limits (HTTP 429) and server overloads (HTTP 503) map to typed exceptions without crashing.
  • Fallback Provider Pipeline: Optional secondary failover via FallbackGemmaProvider activates only if GEMMA_ENABLE_FALLBACK=true, recording model provenance in the summary footer.
  • Coordinator Security Guard & Centralized Auth: Centralized verify_coordinator_authorization in backend.app.api.deps enforces fail-closed authorization across 18 coordinator endpoints (16 mutation routes including volunteers, assignments, relief resources, shelters, alerts, field report reviews, and 2 audit read endpoints).
  • Server-Only Next.js BFF Proxy: Eliminates all browser-exposed coordinator secrets (zero NEXT_PUBLIC_ coordinator keys). Reviews and re-analysis flow through server-side route handlers with origin/CSRF validation and server-only credential resolution.

6. Scientific Validation Phase 1: Defensible Field-Photo Benchmark

To establish a reproducible, evidence-based validation pipeline, Phase 1 defines strict geotechnical boundaries, an expert annotation protocol, and an 18-column manifest:

  • Target Task Triad: Evaluates Target 1 (observable physical indicators: tension cracks, road blockage, etc.) and Target 2 (visual triage priority: low, moderate, high, critical, indeterminate). Target 3 (future failure probability) is explicitly excluded as it requires borehole lithology, slope angle/DEM, and pore pressure.
  • Dual-Expert Protocol: Requires independent blinded review by two geotechnical specialists with Cohen's Kappa threshold (κ ≥ 0.70) to qualify datasets. Disagreements must be adjudicated by a senior geotechnical engineer.
  • Data Leakage Guards & Hashing: Every photograph is fingerprinted with a cryptographic SHA-256 byte digest. Cross-split collisions between train, dev, and test sets are rejected with DataLeakageError.
  • Scientific Uncertainty Metrics: Evaluator computes Wilson score 95% confidence intervals on accuracy, Cohen's Kappa inter-annotator agreement, multi-label indicator F1, and quality-stratified performance.

8. Configuration and Operational Commands

# 1. To run local vision inference with Ollama:
winget install Ollama.Ollama
ollama pull gemma3:4b

# 2. Configure in backend/.env:
GEMMA_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=gemma3:4b
OLLAMA_TIMEOUT=60.0

# 3. Start unified backend server:
python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
Limitations & Ethical Grounding: AI screenings are preliminary triage observations. They do NOT replace professional on-site geotechnical engineering inspections or establish structural clearance for human re-entry.
